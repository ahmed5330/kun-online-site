# SEO-32 — سياسة الصور الحقيقية لشاشات كن أونلاين
تاريخ المراجعة: 15 أكتوبر 2026

## النتيجة الحالية: صور فعلية غير متاحة للاعتماد

تم فحص الملفات الكاملة للفرع `main` في `ahmed5330/kunonline` و`ahmed5330/kun-online-site`:
- تطبيق العملاء يحتوي على الشعار `public/logo.png` فقط؛ لا توجد لقطات PNG/JPG/WebP/SVG موثقة لشاشات الطلبات أو المخزون أو الشحن أو Easy Orders في المستودع.
- صور موقع التسويق البالغ عددها 33 أصلها أغلفة مقالات المدونة، وليست صورًا من واجهة التطبيق.
- لم تُوجد صور لشاشات التطبيق ضمن الآثار المتاحة لفحوصات GitHub Actions المختبرة، ولم نستطع تأكيد إمكانية فتح تطبيق العملاء عبر الفحص الخارجي.
- تصاميم لوحة التحكم التصورية السابقة ليست إثباتًا أنها تعمل على نسخة التطبيق الحالية، ولا يجوز استخدامها مع عبارة «صور حقيقية من السيستم».

**بناءً على ذلك، لم تُنشر أي صورة فعلية ولا ملف خاص بالعميل.** لا يجوز نقل هذه المهمة إلى الحالة مكتملة الصور قبل توفر لقطات أصلية تمت مراجعتها. النطاق المنجز حاليًا: البنية البرمجية وآلية اعتماد ونشر الصور واختبارات الحماية.

## الصفحات المستهدفة عند الحصول على لقطات موثقة

| مسار الصفحة | مثال اللقطة المناسبة | متطلبات الأمان |
|---|---|---|
| `/system/` | لوحة البداية والأقسام الفعلية | حساب تجريبي / إزالة اسم المتجر والمستخدم والأرقام |
| `/system/order-management/` | لوحة الطلبات وتفاصيل طلب تجريبي | لا أسماء أو هواتف أو عناوين أو معرفات عملاء |
| `/system/inventory/` | الأصناف والمتغيرات وحركات المخزون | منتجات تجريبية وعدم كشف مخازن أو أكواد حقيقية |
| `/system/shipping/` | لوحة ما بعد الشحن أو حالة بوليصة تجريبية | لا AWB حقيقي أو بيانات المستلم أو تكاليف حساسة |
| `/system/easy-orders/` | واجهة الربط/المعاينة أو تشخيص محجوب | إخفاء Webhook URL وSecret وأي API Key أو معرف متجر |

## قواعد الالتقاط والنشر

1. التقط اللقطة من **تطبيق كن أونلاين الفعلي** `https://app.kun-online.com/v2/` في بيئة مصرح لك بها. الأولوية لحساب تجريبي ببيانات وهمية صريحة، وليس بيانات عميل حي.
2. راجع أن الشاشة تعرض وحدة موجودة بالفعل وقابلة للفتح. لا تستخدم صورة مولدة بالذكاء الاصطناعي أو تصميم Canva/Figma أو لقطة من واجهة قديمة على أنها نسخة الإنتاج.
3. تأكد أن لقطة الشاشة لا تعرض أسماء العملاء أو الهواتف أو العناوين أو الأرصدة الحقيقية أو رموز الوصول أو أسرار Webhook أو بيانات موظفين أو أرقام الشحن الفعلية. **المراجعة البشرية إلزامية**: فحص الكود لا يكشف الكتابة داخل الصورة.
4. احفظ اللقطة بعد المعالجة الحافظة للخصوصية بصيغة WebP بدون EXIF أو XMP داخل `assets/system-screenshots/` مع اسم ملف آمن أحرف لاتينية صغيرة وشرطات.
5. استخرج SHA-256 للصورة النهائية. أضف صفًا في `seo/system-screenshots.json` يتضمن `id`, `page`, `src`, `status:"approved"`, `sourceUrl:"https://app.kun-online.com/v2/"`, `captureEnvironment`, `capturedAt`, `sourceRevision`, `width`, `height`, `sha256`, `alt`, `caption`, `reviewer` وحقول الموافقات `realUiVerified:true`, `privacyReviewed:true`, `captureAuthorized:true`.
6. شغّل `node scripts/system-screenshots.mjs --write` لتوليد معرض HTML ثابت للصفحات المعنية فقط. ثم `npm test` و`node scripts/browser-qa.mjs` محليًا؛ اختبارات GitHub تراجع الملفات والبصمة والـHTML والعرض على الموبايل.
7. بعد نجاح اختبارات Pull Request، تُدمج صورة واحدة أو مجموعة صور معتمدة. تحقق من **Cloudflare live deployment** بشكل مستقل ولا تساوِ بين نجاح GitHub وظهور الصورة على الموقع.

## الآلية المنفذة الآن

- ملف الاعتماد `seo/system-screenshots.json` يحتوي حاليًا على `screenshots: []`، أي **صفر صور منشورة**.
- توجد مساحات HTML خالية، في صفحات السيستم الخمس، ولا يظهر معرض عام بدون صور معتمدة.
- `scripts/system-screenshots.mjs --check` يمنع إدخال أصل صورة غير معتمد، أو صورة مختلفة البصمة، أو تحتوي على كتل metadata EXIF/XMP، أو إدخال معرض HTML خارج قائمة المراجعة.
- `--write` لا يختلق صورًا؛ بل يُولِّد `figure` و`img` و`figcaption` من أصول فعلية معتمدة.
- فحوصات Playwright تتأكد من عدد الصور المعتمدة وتحميلها عند إضافتها، ولا تكتفي بصورة بديلة.
- هذا العمل في **الموقع التسويقي فقط**، ولا يصل إلى حسابات العملاء ولا يلتقط صورًا تلقائيًا من جلسات المستخدمين.

### ما يمنع الإغلاق الكامل

يلزم الحصول على لقطة أو أكثر أصلية موثقة، والتأكد من صدق البيئة والإصدار، وتنفيذ مراجعة خصوصية بشرية، واختبار ظهور المعرض على الدومين الحي. بدون ذلك تظل حالة SEO-32 **معلقة بسبب غياب صور أصلية معتمدة**.
