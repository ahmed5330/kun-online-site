# نموذج اعتماد دراسة حالة قبل نشرها — كن أونلاين (GEO-04)

> **قالب داخلي فقط. غير مصرح بنشره على الموقع أو مشاركته كدليل أداء.** هذه الخانات لا تثبت واقعة أو نتيجة، ولا تتضمن أي بيانات عميل حقيقية. يُحتفظ بالمستندات الأصلية الحساسة خارج المستودع.

## 1. نطاق الدراسة والموافقة

| الحقل | المطلوب |
|---|---|
| Case ID الداخلي | مُعرّف غير قابل لربطه علنًا بالعميل |
| اسم المتجر العام | اسم وافق صاحبه خطيًا على استخدامه؛ وإلا فلا يُنشر |
| نوع النشاط والسوق | فئة عامة لا تكشف بيانات حساسة |
| فترة الدراسة | تاريخ بدء وانتهاء واضحان |
| نوع دور كن أونلاين | وكالة / سيستم / استشارة / أكثر من ذلك، مع فصل مساهمة كل طرف |
| مرجع الموافقة | رقم موافقة مخزن بشكل آمن خارج GitHub |
| نطاق تصريح النشر | الاسم، الشعار، الصور، الأرقام، الشهادة؛ كل منها يُوافق عليه منفصلًا |
| تاريخ انتهاء التصريح | عند وجوده؛ لا يستمر النشر بعده |
| مسؤول الاعتماد | عضو مخول، بعد تحقق يدوي من صحة الأدلة والتفويض |

## 2. المشكلة والإجراء

**الوضع قبل العمل:** وصف محايد للمشكلة لا يتضمن معلومة شخصية أو سجل عميل.  
**الهدف:** ما المؤشر المطلوب تطويره، ومتى ستتم مراجعته؟  
**التدخل المنفذ فعليًا:** تسلسل زمني مختصر للخدمات أو التعديلات أو الخصائص المستخدمة.  
**الاستثناءات:** هل تغيرت المنتجات أو الميزانية أو السوق أو فترة الحملة أو منصة الشحن خلال التجربة؟

## 3. سجل إثبات كل مؤشر

كرّر الجدول لكل ادعاء رقمي مقترح:

| الحقل | الدليل |
|---|---|
| اسم المؤشر | مثل نسبة تسليم الطلبات |
| التعريف الدقيق | البسط، المقام، التوقيت، مستبعدات القياس |
| مصدر البيانات | منصة/تقرير أصلي، دون تحميل بيانات حساسة في GitHub |
| مرجع تقرير محفوظ | رابط/معرّف داخلي إلى دليل قابل للاسترجاع |
| الفترة السابقة | تاريخ البداية والنهاية |
| الفترة اللاحقة | تاريخ البداية والنهاية |
| القيم | أرقام أصلية تحقّق منها مراجع مستقل |
| وحدة القياس | جنيه، طلب، نسبة مئوية، إلخ |
| قابلية المقارنة | هل اختلاف الموسم أو الميزانية أو حجم العينة أثر على المقارنة؟ |
| مسؤول التحقق | الاسم الوظيفي وتاريخ المراجعة |

**محظور:** تحويل رقم مثال تعليمي إلى نتيجة فعلية، أو عرض ROAS وحده بوصفه ربحًا، أو وصف تحسن في الطلبات المسجلة بأنه تحسن في الطلبات المُسلّمة دون دليل.

## 4. شهادة العميل والأصول

- لا تُكتب شهادة نيابة عن العميل.
- تحفظ نسخة النص الأصلي وتأكيد موافقته على الاقتباس كما هو.
- لا ترفع لقطات قواعد البيانات أو شاشات الطلبات أو عناوين العملاء أو أرقام الهواتف.
- الصورة أو الشعار لا ينشران إلا بعد تصريح مستقل.
- تمنع المراجعات المجهولة أو غير المتحققة من عرضها كـ"تقييم موثوق".

## 5. بوابات النشر

- [ ] الموافقة القانونية/التجارية واضحة ومراجعة يدويًا.
- [ ] أسماء النطاق والصفحات الاجتماعية صحيحة بعد التحقق.
- [ ] كل رقم جوهري له مستند مصدر وفترة ووحدة ومنهج حساب.
- [ ] تم توثيق حدود الاستنتاج والعوامل الخارجية.
- [ ] لا توجد بيانات شخصية أو تجارية سرية.
- [ ] النص وافق عليه العميل بالنطاق المطلوب.
- [ ] أُعدت صفحة عامة أصلية تُراجعها الإدارة تحريريا.
- [ ] اختبارات المصدر/Canonical/Schema/روابط Sitemap ناجحة.
- [ ] النشر مصرح به صراحة، ثم اختُبرت نسخة Production.

### النتيجة المسموح بها

- **غير معتمد:** يبقى داخليًا، ولا توجد صفحة عامة ولا Review/Rating مزعوم.
- **معتمد بشروط:** لا ينشر إلا النطاق المحدد في الموافقة.
- **معتمد للنشر:** يمكن إعداد صفحة دراسة حالة مع فصل البيانات المرصودة عن الرأي والتفسير.

لا يُنشأ `Review` أو `AggregateRating` داخل Schema لاستنتاج نجوم أو تقييمات من شهادات غير معتمدة.
