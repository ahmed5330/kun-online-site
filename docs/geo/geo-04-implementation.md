# GEO-04 — تنفيذ صفحة المنهج وضوابط إثبات الخبرة
**تاريخ التنفيذ:** 27 أكتوبر 2026  
**المستودع:** `ahmed5330/kun-online-site`  
**الفرع:** `feature/geo-readiness-20261027`، PR #89 في وضع Draft، دون دمج أو نشر.

## ماذا نُفذ في الكود؟

1. صفحة جديدة `/methodology/` بمعلومات عملية عن تشغيل المتجر من تسجيل الطلب إلى التسليم والتحصيل، وتعريفات المؤشرات وحدود الاستدلال ومصادر البيانات وحماية معلومات العملاء.
2. `WebPage` و`Organization` و`BreadcrumbList` مرتبطون بنفس معرف الناشر الموجود؛ لا أسماء خبراء مختلقة ولا تقييمات أو ادعاءات عن متاجر بعينها.
3. الوصول إليها من `/about/` وصفحة `/services/ecommerce-management/`، مع إضافة `/methodology/` في `sitemap.xml` و`seo/keyword-map.json` والتحويلات الدائمة و`_worker.js`.
4. أصبح عدد الصفحات المقصودة في المصدر **46 صفحة** بدلاً من 45، بينها 5 P0 و34 P1 و7 P2.
5. `docs/geo/case-study-approval-template.md`: نموذج داخلي للتحقق من إذن العميل والأرقام والمصادر وخصوصية الأدلة **قبل** أي نشر لدراسة حالة.
6. `tests/geo-trust.test.mjs`: اختبارات للمحتوى القابل للقراءة وCanonical/JSON-LD والربط الداخلي وتحويلات المسارات واستمرار خصوصية نموذج الموافقة وعدم فهرسة نموذج إرسال التقييمات.

## تمييز فحص PR عن التحقق بعد النشر

- في فرع التطوير، النسخة المنشورة لا يجب أن تحتوي `/methodology/` قبل اعتماد الدمج والنشر. لذلك `scripts/geo-site-audit.mjs --live` يَعرض فرق Sitemap في `liveSitemap.pendingDeployment`، ويُسمح بهذا الفرق **فقط** إذا كان `GEO_ALLOW_UNDEPLOYED_ROUTES=1` في فحص PR.
- عند التحقق على `main` أو بعد الإنتاج، يُترك المتغير معطلًا، فيصبح تطابق جميع عناوين Sitemap مع المصدر شرط نجاح صارم.
- قراءة محتوى HTTP مع تغيير User-Agent ليست دليل سماح لزاحف موثق؛ يلزم الرجوع إلى Cloudflare Security Events.
- وجود صفحة جديدة في Sitemap لا يثبت أن Google فهرسها، ولا يوجد تعهد بأن ChatGPT أو Bing سيستشهدان بها.

## ما لم يُنجز بعد، عمدًا

- دراسات الحالة والشهادات العلنية وأسماء أعضاء الفريق لم تنشر، لأن موافقة أصحاب البيانات ومصدر الأرقام والمراجعة البشرية غير متوفرة في هذا التغيير.
- إعدادات Cloudflare وSearch Console وBing Webmaster Tools لم تُغيّر.
- لا توجد مراجعة أداء حقيقية من الذكاء الاصطناعي ضمن هذا التغيير؛ يتطلب الأمر بيانات قابلة للقياس وخط أساس.
- بقيت صفحة `/reviews/` المخصصة لجمع التقييمات `noindex` وخارج Sitemap كما كانت.

## متطلبات اعتماد الإصدار

1. نجاح `npm test` بما فيها اختبارات GEO وثبات خط إنتاج المقالات.
2. نجاح اختبارات متصفح Desktop/Mobile ومراجعة شكل صفحة `/methodology/` وروابطها على Preview.
3. عدم المساس بالمدونة أو طلبات العملاء أو `app.kun-online.com`.
4. موافقة مراجعة PR ثم نشر معلن، وليس مجرد دفع commits.
5. بعد النشر: رد HTTP 200 للصفحة الجديدة، تحويل 301 للمسارين القديمين، Meta/Canonical/Schema صحيحة، تطابق Sitemap مع الإصدار الحي، ثم URL Inspection والمتابعة في أدوات القياس.
