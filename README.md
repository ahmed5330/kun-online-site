# كن أونلاين — الموقع التسويقي

الموقع: https://kun-online.com — الواجهة والخدمات وصفحات السيستم التعريفية ومدونة التجارة الإلكترونية. تطبيق العملاء منفصل على https://app.kun-online.com/v2/.

## هيكل الصفحات

- `/`: الصفحة الرئيسية العربية.
- `/en/`: الصفحة الإنجليزية.
- `/gulf/`: صفحة أسواق الخليج.
- `/services/` و`/system/`: خدمات الوكالة والصفحات التعريفية بالنظام.
- `/blog/` و`/blog/<slug>`: المدونة والمقالات.
- `/sitemap.xml`: خريطة الموقع العامة.

## نشر المقالات — بدون OpenClaw أو VPS

يستخدم الموقع GitHub Actions عبر `.github/workflows/scheduled-blog-publisher.yml`،
الذي يعمل يوميًا الساعة **09:17 صباحًا بتوقيت القاهرة (Africa/Cairo)**، وقد يتأخر التشغيل الفعلي طبقًا لجدولة GitHub.

الناشر لا يولد نصوصًا تلقائيًا، ولا يعتمد على Claude API أو `ANTHROPIC_API_KEY`.
ينشر بحد أقصى **مقالًا واحدًا معتمدًا تحريريًا في اليوم** من ملفات `content/approved/` الجاهزة بعد اجتياز فحوص المحتوى والكود.
إذا لم توجد مقالات معتمدة مؤهلة، لا يحدث أي نشر. يحتفظ بسجل النشر في `content/publication-log.json`.
ملفات الموافقة الأصلية تظل في GitHub للتدقيق، لكن السجل يمنع نشرها مرة ثانية حتى في اليوم التالي؛ وأي تعارض بين السجل وقائمة المقالات وخريطة السلسلة يوقف النشر بدل التكرار.

### اختبار الناشر وتشغيله

1. افتح GitHub → **Actions** → **VPS-free blog publisher**.
2. استخدم **Run workflow** مع `dry_run=true` للفحص دون نشر.
3. عند الاعتماد التحريري الفعلي يمكن تشغيل `dry_run=false` يدويًا؛ وتظل قاعدة مقال واحد في اليوم سارية.
4. راجع نتائج اختبارات GitHub Actions وفحص Cloudflare والرابط الجديد بعد النشر.

لإضافة مقال جديد راجع `content/approved/README.md`. اختبارات الموقع: `npm test`.
خريطة خطة المئة مقال في `seo-content-map.json`، وسجل المقالات العامة في `blog/articles.json`.

## الاستضافة والفهرسة

النشر العام على **Cloudflare Pages** المتصل بـ GitHub. اجتياز الفحوص أو إدراج الرابط في Sitemap لا يثبت أن Google فهرسه؛ يجب استخدام تقرير **Pages** و**URL Inspection** في Google Search Console لتأكيد حالة كل صفحة. لا تعلن فهرسة أو إرسال طلبات فهرسة بدون تحقق مباشر.


## خط الإنتاج والتحقق من الاستمرارية (تحديث 17 أكتوبر 2026)

- خطة السلسلة المرجعية: `seo-content-map.json`، مع منع إعادة نشر المواضيع من `seo/published-series-mapping.json`.
- الإنتاج التحريري: مهمة ChatGPT المجدولة المنفصلة (عند توافر أدوات GitHub في تشغيلها) تبحث وتحرر مقالًا واحدًا وتحفظ HTML وmetadata معتمدة إلى `content/approved/`. إذا فشلت المهمة، لا يستطيع GitHub Actions كتابة مقال بديل من تلقاء نفسه.
- قائمة المقالات المقبلة: انظر `scripts/editorial-production-status.mjs --json`. المسار `blog-editorial-production.yml` يراقب المخزون ويحدّث GitHub Issues إذا قل عن 3 مقالات.
- صور المقالات: `scripts/generate-approved-covers.py` يرسم غلافًا عربيًا حقيقيًا 1200×630 باستخدام Noto وPillow دون سيرفر أو مفتاح مدفوع. لا يعيد كتابة صور المقالات المنشورة.
- اختبار المقالات المستقبلية: `blog-queued-preflight.yml` يحاكي تاريخ إتاحة آخر مقال معتمد، ويولّد الأغلفة مؤقتًا ويفحص **كل المقالات المعتمدة المؤهلة** دون نشر؛ بوابة `npm test` لا تسمح بتمرير أخطاء SEO والروابط.
- النشر العام: `scheduled-blog-publisher.yml` يعمل عند 09:17 و15:37 بتوقيت القاهرة بالإضافة إلى التشغيل اليدوي وعند إضافة مقالات معتمدة؛ قفل تاريخ القاهرة يمنع أكثر من مقال في اليوم. النجاح لا يُعتبر مُثبتًا حتى كتابة commit وتحقق خدمة Cloudflare من عنوان المقال وSitemap.
- لا يعتمد سير العمل على خدمة GitHub Models (أُوقفت في يوليو 2026). `scripts/generate_article.py` القديم محظور تشغيله مباشرة لأنه كان يتجاوز بوابات الجودة ويتعامل مع محتوى 800–1200 كلمة.
- **حدود الفهرسة:** اختبارات HTTPS/Canonical/Sitemap تبرهن القابلية الفنية فقط؛ لا يمكن ادعاء Google-indexed من دون بيانات URL Inspection/Page Indexing صحيحة، والحقل `indexed` عبر Windsor.ai قديم وغير موثوق.
