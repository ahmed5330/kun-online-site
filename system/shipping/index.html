برنامج إدارة الشحن والبوليصات والمرتجعات

📦

بوليصات J&T Express

تظهر في كود التطبيق واجهات لإعداد بيانات الشحنة ومراجعة الطلب قبل إرساله، مع مسارات للتعامل مع رقم البوليصة؛ الإنشاء الحقيقي يعتمد على الحساب وتفعيل الناقل.

🚚

تتبع الشحنات وحالة الأوردر

توجد وحدات لعرض تحديثات J&T الواردة، ومحاولة تحديث الحالة عند الحاجة مع ضوابط لتجنب الطلبات المتكررة. حالة الصفحة لا تُعد إثباتًا للتسليم دون بيانات ناقل موثوقة.

📑

استيراد شيتات شركات الشحن

قراءة ملفات CSV وXLSX وتعيين أعمدة البوليصة والحالة والمصاريف، مع معاينة المطابقة قبل تحديث الأوردرات. قوالب الشركات ليست تكامل API مباشرًا معها.

↩️

إدارة المرتجعات والاستبدالات

لوحات لتصنيف المرتجع والاستبدال والإلغاء وتسجيل السبب، ومراجعة حالة الطلب بعد التسليم؛ فحص القطع وإعادتها للمخزون يحتاج دورة عمل مخزن مُفعلة.

💰

تكاليف الشحن وCOD

مسارات لفصل ما يدفعه العميل عن تكلفة الشحن على المتجر، ومراجعة مبالغ التحصيل في بيانات الشيت؛ المطابقة المحاسبية لا تُفترض من مجرد وصول تحديث الحالة.

🔒

ربط الشحن بالمخزون والصلاحيات

عناصر لحماية تحديث الأوردر عند وجود تعارض بالمخزون، وربط القطعة المشحونة بالطلب. فعالية المسح والتجهيز وتسليم المندوب تحتاج اختبار قبول عملي.

الخطوات دي توضح شكل المتابعة المقصود، مش وعد بأن كل مرحلة مكتملة تلقائيًا؛ تحديث الحالة أو إصدار البوليصة يستند لمصدر موثوق وصلاحيات واضحة.

فرق مهم في التكاملات

تكامل J&T المباشر مختلف عن استيراد شيت شركة الشحن

فيه فرق بين ربط شركة شحن بخدمات API وWebhook وبين رفع ملف حالات الشحن. الاتنين ممكن يساعدوا في المتابعة، لكن مش نفس مستوى الأتمتة أو إثبات وصول الشحنة.

🔗

J&T Express

توجد واجهات لإعداد بيانات الشحنة وتتبع حالتها عبر التكامل المهيأ، بما في ذلك عرض رقم البوليصة والتحديثات. تجربة إنشاء شحنة حقيقية أو إلغائها تتطلب موافقة وإعدادًا آمنًا.

📂

CSV / XLSX

تظهر قوالب استيراد نتائج الشحن لشركات متعددة: تعيين عمود AWB والحالة والتكاليف، ثم مطابقة الصفوف قبل تعديل الأوردرات. اسم الشركة في القائمة لا يثبت اتصال API حيًا بها.

💵

الدفع عند الاستلام COD

توجد مسارات لتحليل رسوم الشحن والمبلغ المطلوب تحصيله ومقارنته بحالة التسليم. التسليم لا يساوي التحصيل؛ لازم مراجعة كشف الناقل والحسابات قبل اعتبار الإيراد مستلمًا.

تنبيه: حالات «تم الشحن» و«تم التسليم» و«تم التحصيل» مختلفة. إصدار بوليصة لا يؤكد أن الطرد خرج فعليًا، ووصول حالة مسلّم لا يثبت تسوية المبلغ المستحق تلقائيًا.

المرتجعات والاستبدالات

إزاي تراجع الشحنات الراجعة من غير ما تلخبط المخزون والأرقام؟

الوحدة البرمجية فيها لوحات لتصنيف المرتجع والاستبدال والإلغاء وتسجيل الأسباب، لكن معالجة القطع المرتجعة مرتبطة بفحص المخزون واعتماد الحالة. لا يصح اعتبار كل طرد راجع صالحًا للبيع مباشرة.

↩️

إثبات نتيجة الشحنة

مراجعة البوليصة والتاريخ والحالة المرتبطة ببيانات شركة الشحن، والتمييز بين إلغاء قبل الشحن ومرتجع بعد الخروج.

📦

فحص القطع الراجعة

ربط حالة المرتجع بالقطع بعد استلام المخزن وفحصها: برنامج إدارة المخزون والباركود يشرح متطلبات التتبع والجرد والهالك.

🧾

التسوية المالية

التحصيل ورسوم الشحن والرسوم العكسية تحتاج مراجعة منفصلة بحسب بيانات الناقل والعقد، ولا تُستنتج من تغيير حالة أوردر فقط.

قبل تشغيل التكامل

قائمة تحقق لربط الشحن والبوليصات بأمان

اختبارات الشحن والناقل الموثقة في المستودع قد تعتمد محاكاة بدل إرسال شحنة حقيقية. التحقق الحي من J&T وبيانات المستخدمين وعمليات المخزن المطلوبة لا يُستبدل بوجود الكود.

  1. تهيئة شركة الشحن: التحقق من الحساب والصلاحيات والمفاتيح والبيئة الصحيحة للناقل.
  2. بيانات العميل والعنوان: مراجعة اسم المستلم وعنوانه ومنطق المحافظة والمنطقة والرقم.
  3. البوليصة وعدم التكرار: اختبار إنشاء طلب تجريبي آمن ومنع ازدواج نفس الشحنة أو التكرار بعد فشل الاتصال.
  4. التتبع: التأكد من وصول تحديثات الحالة وربطها بنفس رقم البوليصة والأوردر.
  5. المخزون وتجهيز القطع: مطابقة محتوى الطرد والباركود والجرد قبل تحديث حالة الشحن.
  6. المرتجع والاستبدال: فحص الحالة وإثبات سبب الارتجاع والتسوية قبل إعادة القطع للمخزون.
  7. التحصيل والمصاريف: مطابقة COD ورسوم الشحن مع كشوف الشركة والنظام والحسابات.
  8. صلاحيات التشغيل: التأكد من عزل المتاجر ومَن يستطيع إنشاء بوليصة أو تعديل حالة أو اعتماد تسوية.

النشر الناجح لصفحة التسويق لا يثبت تشغيل التكامل. تأكد من إعداد J&T ونتائج اختبار القبول قبل إصدار بوليصات أو إلغاء شحنات أو تسوية COD في الإنتاج.

برنامج ولا خدمة؟

برنامج إدارة الشحن غير التعاقد مع شركة شحن أو فريق تشغيل

كن أونلاين يساعد في تنظيم بيانات الأوردر والبوليصة والمتابعة داخل النظام، لكن لا يحل محل شركة النقل ولا يعني توفير مندوب أو شحن مجاني. فرق التشغيل أو متابعة العملاء خدمة مستقلة عن ترخيص البرنامج.

راجع برنامج إدارة الطلبات لمعرفة رحلة الأوردر، وخدمة تشغيل المتاجر إذا كنت تحتاج فريقًا لتنفيذ المهام. أسعار خدمات الوكالة لا تمثل تلقائيًا اشتراك السيستم أو تعرفة شركة الشحن.

أسئلة متكررة

أسئلة شائعة عن برنامج إدارة الشحن والبوليصات

هل برنامج كن أونلاين ينشئ بوليصة J&T؟

توجد في الكود واجهات ومسارات لإنشاء الشحنة والتعامل مع رقم البوليصة عبر J&T. نجاح الإنشاء الفعلي يتطلب إعداد تكامل صالح وتجربة معتمدة، ولا نؤكد أن الوظيفة مفعلة لكل متجر.

هل أقدر أتابع الشحنة من داخل النظام؟

توجد مسارات لعرض تحديثات شحن J&T والتعامل مع تحديثات الويبهوك أو طلب الحالة بشروط. دقة الحالة تعتمد على بيانات الناقل وأكواد الربط.

هل الشيتات تدعم غير J&T؟

هناك قوالب CSV وXLSX لأسماء شركات منها Bosta وMylerz وAramex وغيرها، لكن القالب لاستيراد الملف فقط، ولا يدل على تكامل مباشر فعّال مع كل شركة.

ما معنى رقم AWB أو رقم البوليصة؟

هو معرف الشحنة لدى الناقل؛ يفيد في مطابقة الأوردر بتحديثات التتبع وكشف التسليم أو المرتجع. لا يجب اعتباره دليل تسليم نهائيًا بمفرده.

المرتجع بيأثر على المخزون والأرباح إزاي؟

المرتجع يحتاج تصنيفًا وفحصًا ومراجعة ما تم تحصيله أو خصمه، مع ربط القطع بالمخزون إن كانت مفعلة. التحديث المالي يحتاج مطابقة قبل اعتباره نهائيًا.

هل النظام يشحن الطلب تلقائيًا لكل شركات الشحن؟

لا. نوع التكامل المدعوم ومفاتيحه وإعدادات المتجر تحدد الإمكانيات. رفع شيت لشركة لا يعني أنها متصلة عبر API.

هل خدمة فريق الشحن جزء من اشتراك السيستم؟

البرنامج أداة تشغيل، أما خدمة إدارة وتشغيل المتجر فهي عمل بشري باتفاق مستقل. كذلك أسعار خدمات الوكالة ليست بالضرورة رسوم اشتراك السيستم.
